# ARTCOVR — Full-System Production Readiness (Evidence-Based Plan)

## Verdict on Current State (What We Have)
The codebase is **more mature than a "partially correct attempt"** — the backend is genuinely well-engineered:
- **Commerce is idempotent, reconciling, and server-authoritative.** `reserve_artwork` takes a `pg_advisory_xact_lock` and locks the `artworks` row `FOR UPDATE` *first* (settlement-lock invariant holds: `202608110004_rpcs.sql:22`, `202608140009_convergence_hardening.sql:55-63`). `stripe-webhook` verifies signature, dedupes via `stripe_events`, reconciles out-of-order/duplicate/foreign events, and revokes/restores access on dispute/refund (`supabase/functions/stripe-webhook/index.ts`). Client never sends price/currency to Stripe — amount is re-derived from DB at reservation.
- **Security model is strong.** All tables + `storage.objects` are `REVOKE`d from anon/authenticated; every privileged read/write goes through Edge Functions with service role (`202608110003_rls_storage.sql`). Signed URLs are short-lived (300s) and only issued to entitled rows (`my-images`).
- **Catalog is a build-time static projection.** Frontend display uses `curated-public.json` (committed, generated by `scripts/catalog/`), NOT the DB. `next.config.ts` is `output: "export"` (static) deployed to Vercel (`out/`). `verify-export-isolation.ts` runs post-build to guarantee no unapproved slug ships.
- **Theme:** `light`/`dark` only in code; `red` deprecated in storage and falls back to `light` (`layout.tsx` bootstrap + `useTheme.ts`).

The work needed is **not a rebuild** — it is: (1) prove the suite is green, (2) remove dead surface, (3) close the one real drift risk (DB↔JSON catalog coherence), (4) align the two nav systems, (5) verify runtime/deploy, (6) tighten CSP.

## Ground Truth (File References)
- Frontend catalog source of truth: `src/lib/artcovr/curated-public.json` (populated: e.g. `cart-of-hours` $200 exclusive). Display logic: `src/lib/artcovr/artworks.ts`.
- Reservation/settlement source of truth: DB `artworks` (`catalog_id`, `is_listed`, approvals) via `reserve_artwork`.
- Two component families: `components/parity/*` = immersive **home** (`page.tsx`); `components/artcovr/*` = **interior** pages (product/checkout/archive/my-images/etc.).
- Deploy: `next.config.ts` (`output:"export"`), `public/vercel.json` (`outputDirectory:"out"`, redirects `/bag`→`/archive`, `/shipping-and-return`→`/refunds`, security headers).
- Verify gate: `npm run verify` = test + typecheck + lint + build (build also runs `prune-deployment-assets` + `verify-export-isolation`).

## Failure Classes Mapped to Real Findings
- **WRONG BEHAVIOR (suspected, unproven):** DB↔JSON catalog drift → a visitor sees a work they cannot buy, or a bought work is invisible. Root cause: dual source of truth (build-time JSON vs runtime DB). Must be proven/disproven in Phase 0.
- **WRONG IMPLEMENTATION:** Two nav/header systems (`parity/Header`+`parity/ThemeSwitcher` vs `artcovr/SiteHeader`+`artcovr/ThemeToggle`). Risk of inconsistent nav/links between home and interior. CSP `script-src 'unsafe-inline'` (static-export tradeoff) weakens XSS defense.
- **WRONG EXISTENCE:** Dead components with zero imports: `parity/BackToTop.tsx`, `parity/ScrollToTop.tsx`, `parity/ProductCard.tsx`. (Note: `ThemeSwitcher`/`TiltedCarousel`/`SpiralScroll` ARE live via `ScrollJourney`/`Header` — do NOT remove.) Redirect stub pages `bag/page.tsx`, `shipping-and-return/page.tsx` duplicate config redirects (harmless safety net; keep).
- **WRONG ABSENCE:** No operator UI for stuck `reserved`/`pending` purchases — must confirm `commerce-watchdog` scheduled function covers them. No order-history beyond `my-images` (acceptable for MVP).
- **WRONG PLACEMENT:** None material. Price/entitlement stay server-side (correct). Catalog split is intentional for static export.

## Failure Graph (Top Findings)
**F1 — Catalog coherence (highest leverage).**
SYMPTOM: potential see-but-can't-buy / bought-but-invisible. ROOT CAUSE: display catalog (JSON) and reservation catalog (DB) are separate sources; coherence depends on the projection script. SHARED ASSUMPTION: "projection keeps them in lockstep." BLAST RADIUS: checkout failures, orphaned purchases, support load. IMPACT: lost revenue / broken trust. CORRECTION: add a contract test asserting every `curated-public.json` slug maps to an `is_listed`+approved DB row and reserve succeeds; assert reverse. PROOF: test + manual reserve attempt on a displayed slug.
**F2 — Dead surface.** SYMPTOM: unused files ship. ROOT CAUSE: incomplete negative-code pass after parity/artcovr split. CORRECTION: delete 3 dead components. PROOF: grep import count = 0 after delete; `npm run lint` clean.
**F3 — Nav coherence.** SYMPTOM: home vs interior may expose different links. ROOT CAUSE: two Header implementations. CORRECTION: extract one shared nav config; align both headers. PROOF: visual diff + E2E nav check.
**F4 — CSP.** SYMPTOM: `unsafe-inline` scripts allowed. ROOT CAUSE: static export cannot use per-response nonces. CORRECTION: keep only trusted inline; consider `script-src` hash of the two known inline blocks; document residual risk. PROOF: security-headers test.
**F5 — Unknown baseline.** SYMPTOM: unknown. ROOT CAUSE: `npm verify` not yet run this session. CORRECTION: run it; fix first. PROOF: green verify.
